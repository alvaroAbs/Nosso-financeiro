Conta, login e dados compartilhados

Nosso Dinheiro · versão 4.2 · guia rápido (10 a 15 minutos, tudo no plano grátis)

o que muda

Antes, o app guardava tudo só no navegador de um aparelho. Agora existe uma tela de entrada e, com um projeto gratuito do Firebase, uma casa compartilhada: você e seu cônjuge entram cada um com o próprio e-mail e os dois veem e editam os mesmos dados, em qualquer celular ou computador.

O app nunca cria a sua conta do Firebase por você — esses passos são seus, no site do Google, e são gratuitos.

1. Criar o projeto no Firebase (grátis)

  1. Acesse console.firebase.google.com com a sua conta Google e clique em Adicionar projeto. Dê um nome (ex.: nosso-dinheiro) e conclua. O plano Spark é gratuito e suficiente.
  2. No menu lateral, abra Authentication → Get started → aba Sign-in method → ative E-mail/senha e salve.
  3. Abra Firestore Database → Criar banco de dados → escolha Modo de produção → localize a região (ex.: southamerica-east1) → criar.
  4. Clique no ícone </> (Web) em “Seus apps”, registre o app e copie o bloco firebaseConfig que aparece.

2. Colar a configuração no app

  1. Abra o app → aba 🔗 Compartilhar → cartão 👤 Conta & nuvem → botão ☁️ Ativar nuvem.
  2. Cole o firebaseConfig inteiro (com chaves e vírgulas) e clique em Salvar configuração.
  3. Volte para a tela de entrada: crie a sua conta com e-mail e senha e dê um nome à casa. Você recebe um código de convite tipo CASAL-K7QM4821.

3. Chamar a segunda pessoa

  1. Mande o link do site + o código de convite para o seu cônjuge (WhatsApp serve).
  2. No aparelho dele(a): abrir o site → Criar conta com o e-mail dele(a) → na aba Entrar, usar “já tenho um código de convite” e colar o código.
  3. Pronto: a partir daí tudo que um lança aparece no outro em segundos (e o app mantém uma cópia offline no aparelho).

4. Regras de segurança do Firestore

Sem isso, qualquer pessoa com a chave do site poderia ler dados. No Firebase: Firestore Database → Regras, cole o bloco abaixo e publique.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    match /casas/{casaId} {
      // só quem está na lista de membros lê
      allow read: if request.auth != null
        && request.auth.uid in resource.data.membros;
      // quem cria entra como membro
      allow create: if request.auth != null
        && request.auth.uid in request.resource.data.membros;
      // membro atualiza; quem tem o código pode se adicionar aos membros
      allow update: if request.auth != null
        && (request.auth.uid in resource.data.membros
            || request.auth.uid in request.resource.data.membros);
      allow delete: if false;
    }

    match /usuarios/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}

Com essas regras, apenas as duas contas da casa conseguem ler ou gravar os dados daquela casa. O código de convite deixa a segunda pessoa entrar uma única vez na lista de membros.

5. O que é o PIN (e o que ele não é)

O PIN é só uma trava de privacidade do aparelho. Ele impede que alguém que pegue o seu celular abra o app, e fica guardado apenas naquele navegador. Ele não criptografa os dados e não substitui a senha da conta. A segurança de verdade vem do login (Firebase Authentication) e das regras acima.

6. Rotina dos dois

  • Offline: pode lançar sem internet; ao voltar a conexão, o app envia sozinho.
  • Conflito: se o aparelho tiver dados mais novos que a nuvem, o app pergunta qual manter (enviar os meus ou usar os da nuvem).
  • Recibos grandes: acima de ~800 KB o envio à nuvem deixa as fotos só no aparelho, para não estourar o limite gratuito; o resto dos dados sincroniza normal.
  • Sair: cartão da conta → Sair da conta. O app volta para a tela de entrada.
  • Sem nuvem: o botão “Usar só neste aparelho” continua existindo — nada do que você já tinha foi perdido.

7. Problemas comuns

MensagemO que fazer
“Nuvem não configurada”Falta colar o firebaseConfig (passo 2).
“Ative E-mail/senha no Firebase Authentication”Authentication → Sign-in method → ativar E-mail/senha.
“A nuvem negou o acesso”Regras do Firestore não publicadas (passo 4) ou você não está na lista de membros — use o código de convite.
“Código não encontrado”Confira as letras/números (o código não tem O nem 0 ambíguos); peça para o outro abrir o cartão da conta e copiar de novo.
Dados não aparecem no outro celularConfirme que os dois estão na mesma casa (mesmo código de convite) e toque em 🔄 Sincronizar agora.
